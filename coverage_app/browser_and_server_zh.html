浏览器和本地服务器是怎么配合的

DSA Coverage 应用（coverage_app/）里两个问题的回答。背景：/api/generate 不是 Claude 或任何云端 API， 而是本机上 server.py 自己定义的一个地址，请求不出这台电脑，也不需要网络和 API key。

问题 1“send request” 到底发到了哪里？

你的问题：Click handler 里 send request，这不是我的 local server 吗？意思是从 local server 发请求给 local server 吗？
不是自己发给自己。你的电脑上同时运行着两个独立的程序：浏览器和 Python 进程。 “send request” 是浏览器发给 Python 进程（server.py）。
程序角色里面运行什么
浏览器客户端：显示页面、响应你的点击index.html、app.js
Python 进程服务器：干活（跑 Python）并回复server.py → check_coverage_database.py
  1. 启动双击 start.command，运行 server.py，这个 Python 程序在后台等待 127.0.0.1:8765 上的请求。
  2. 打开页面浏览器向服务器要页面，服务器把 index.html、app.js、app.css 这几个文件发给浏览器。
  3. 代码在浏览器里运行从这一刻起，app.js 是在浏览器里运行的，不是在服务器里。服务器只是把文件“递”了过去。
  4. 点击 Generate浏览器里的 app.js 执行 api("/api/generate", body)，通过本机网络连接把请求发给 Python 进程。 地址里没写域名，所以默认发回打开这个页面的同一个地址：http://127.0.0.1:8765/api/generate。
  5. Python 进程处理server.py 的 do_POST 收到请求，调用 check_coverage_database.main()。 浏览器里的 JavaScript 本身不能运行 Python，所以只能请 Python 进程来做。

之所以感觉像“local 发给 local”，是因为两个程序在同一台电脑上，请求从不离开这台机器。但确实是两个程序在对话：浏览器提要求，Python 进程干活并回复。

问题 2浏览器是在 server.py 里打开的吗？

你的问题：双击 start.command 会先启动 server.py，然后自动打开浏览器。那浏览器是在 server.py 里打开的吗？还是两者是分开的、同时触发的两件事？
两者都对一部分：浏览器是 server.py 让 macOS 打开的，但打开以后，浏览器就是完全独立的程序。 而且 start.command 并没有同时做两件事，它只做一件事（运行 server.py），后面是一条链。

coverage_app/server.py 的 main() 里就是这一行：

threading.Timer(0.8, lambda: webbrowser.open(url)).start()

webbrowser.open(url) 是 Python 自带的标准库，作用是告诉 macOS“用默认浏览器打开 http://127.0.0.1:8765”， 和你在邮件里点一个链接的效果一样。等 0.8 秒，是为了让服务器先启动好。

为什么说它们是分开的

关掉浏览器标签服务器照样运行。重新打开 http://127.0.0.1:8765，页面就回来了。
输入 q 停掉服务器页面还开着，但按钮不再起作用，因为没有程序回复了。
输入 r 重启不会再打开新的浏览器（带了 --no-browser），刷新原来的标签页即可。

涉及的文件：coverage_app/start.command、coverage_app/server.py（main()、do_POST、start_job）、 coverage_app/static/app.js（Generate 按钮的点击处理）。完整链路和行号见 coverage_app/how_it_works.html。
