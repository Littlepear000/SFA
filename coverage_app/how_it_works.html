How the coverage app works

Overview

A. Generate coverage database

The button is on the Generate tab. The browser never runs Python itself: it sends the paths to the local app server, and the server runs the script in a background thread.

  1. 1

    The button

    Browser
    <button id="btn-generate">

    Plain HTML. Next to it on the page: the Final CSV box (in-csv), the Staff reports folder (in-pdf), the subfolder chips and the Version stamp.

  2. 2

    Click handler: send the request

    Browser
    $("btn-generate").addEventListener("click", …)

    Re-checks the paths (inspectPaths() → POST /api/inspect), collects the ticked subfolders, then posts {final_csv, pdf_root, batches, stamp} to /api/generate through api() (line 22, a small fetch wrapper). Then starts polling.

  3. 3

    Server receives the POST

    App server
    Handler.do_POST()

    Routes /api/generate to start_job().

  4. 4

    Check inputs, start a background thread

    App server
    start_job(body)

    Checks the CSV and folders exist, the stamp is valid, and no other run is going. Makes the stamp unique (unique_stamp(), line 93: adds _2, _3 …), then starts _run_job in a thread and answers at once, so the page does not freeze.

  5. 5

    The line that runs the Python code

    App server
    _run_job() → ccd.main(final_csv=…, pdf_root=…, out_dir=…, stamp=…, batches=…, progress=_progress)

    ccd is check_coverage_database, imported at server.py:46. Its printed output is captured into the job log (_LogWriter), and _progress() (line 172) updates the progress bar. It is the same main() you get with python code/check_coverage_database.py.

  6. 6

    main(): build, write the version

    Python script
    main()

    Calls build(), then by_year(), then writes the workbook and the run record (JSON with the CSV's size, modified time and SHA-256).

  7. 7

    build(): one row per country and year

    Python script
    build()
    • Values: load_rows() reads the final CSV and gives each row the year the value is for; country names via normalize_country().
    • Staff reports: read_pdfs() lists the PDFs in the chosen subfolders and reads country + publication year from the file name; keep_panel_reports() drops regional reports; report_country_years() gives the (country, year) pairs.
    • Source of each value: value_sources() picks Round 1 → Round 2 → Round 3 → Gap fill when several rounds give a value.
    • Indicator columns: indicator_columns() names one column per hierarchy_id (h6_residual …).
  8. 8

    Saved to output/coverage/

    Files
    write_workbook()

    coverage_database_<STAMP>.xlsx with sheets Coverage (Yes/No), By year, Sources, Report years, Indicators, Notes; and coverage_database_<STAMP>.json (the version record). Folder set by OUT_DIR in the script's settings.

  9. 9

    Progress bar and version history

    Browser
    pollJob() → GET /api/job

    Asks the server every second how far the run is (setJobState(), line 99, draws the bar). When done, loadRuns() (line 164 → GET /api/runs → list_runs() in server.py line 65) reloads the version list, which is simply every coverage_database_*.xlsx + .json in the folder.

B. Dashboard

Where the analysis is. It is split in two:
① The Python script works out the facts per country and year (has a value? from which round? which years have a staff report?) and saves them in the workbook, in build().
② The summary statistics you see (counts per year by source, Unavailable, the T+1…T+4 split, the three numbers at the top) are counted in the browser, in app.js: yearBreakdown() and drawChart(). That is why switching the indicator or T+k is instant: nothing is re-run in Python.
The workbook's "By year" sheet (by_year(), script line 303) is a separate summary for Excel; the Dashboard does not read it.
  1. 1

    Pick a version

    Browser
    setActive(stamp)

    Runs when the Version dropdown changes (or on start). Requests GET /api/runs/<stamp>/data; the answer is kept in S.data and feeds both the Database and the Dashboard tab.

  2. 2

    Route the request

    App server
    Handler.do_GET()

    Finds the workbook for the stamp (workbook_for(), line 87) and calls coverage_payload().

  3. 3

    Read the saved workbook, send it compact

    App server
    coverage_payload(path)

    Reads the sheets with pandas and sends, for 4,750 rows: the country and year of each row; per column a string of 1/0 (from Coverage); per indicator a string of source codes 1 2 3 g 0 (from Sources); per country its publication years (from Report years). No counting happens here.

  4. 4

    Indicator slicer and T+k switch

    Browser
    setupSlicer()
    setSpan(k)

    Each change calls drawChart() again. The buttons themselves are in index.html:147.

  5. 5

    The summary statistics

    Browser
    yearBreakdown(ind, k)
    reportLookup()
    • Goes through all country-year rows once. For each year: total, and per source r1 r2 r3 gf from the source code of the chosen indicator; code 0 counts as unavail.
    • With T+k on: for an unavailable country in year T, checks the country's report years (from reportLookup()) for T+1 … T+k. None found → nolater (the hatched part, name added to list); otherwise later.
    • partial marks years where T+k goes past the last year with PDFs (the *).
  6. 6

    Draw it

    Browser
    drawChart()

    The three numbers at the top (country-years, with data, coverage %), the stacked columns (SVG), the count above each column, the tooltip, the country list when a column is clicked, and the "Show the numbers" table, all from the rows of yearBreakdown().
