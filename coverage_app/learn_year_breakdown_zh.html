Dashboard 的计数由 coverage_app/static/app.js 的 yearBreakdown()（第 399 行）在浏览器里算出。 这页教你拿到同一份数据 S.data，再用 Chrome DevTools 一行一行地跑，看每一步的结果。

问题切回 Dashboard 后页面“卡住”了

你的问题：按逐行运行走完第四步后，再切回 Dashboard，出现了一个奇怪的页面。
最常见的原因：代码停在断点上还没继续。暂停期间整个页面的 JavaScript 都冻结了， 点标签、点按钮都没有反应，图表也可能只画了一半或是空的。这不是坏了，按 F8（或页面顶部的 ▶）继续就好。

处理办法

  1. 继续运行按 F8 或黄条上的 ▶。如果又停住，说明断点又被触发了，见下一步。
  2. 关掉断点第 400 行的断点会一直留着（刷新页面也在）。每次 Dashboard 重画都会再停一次： 切到 Dashboard、换 Indicator、点 T+k、甚至拖动窗口大小。去掉的办法任选一个：
    · 再点一下蓝色的行号 400，取消断点；
    · 右侧 Breakpoints 面板里取消勾选；
    · 按 Cmd+F8 暂时停用所有断点（再按一次恢复）。
  3. 如果图表是空的继续运行后切一下别的标签再切回 Dashboard，或刷新页面，图会重新画出来。

你描述的“以下这个页面”截图没有传过来。如果看到的不是上面这种灰色暂停界面（比如报错信息或空白），把截图再发一次。

第一步拿到 S.data

直接在 Console 输入 S.data 会报 S is not defined：整个 app.js 包在 (function () { … })(); 里，S（第 32 行）是私有变量。两种办法：

办法 1：停在断点时查看

  1. 设断点DevTools（Cmd+Option+I）→ Sources → app.js，点第 400 行的行号。
  2. 触发切到 Dashboard，或点一下 T+3，代码停住。
  3. 打印在 Console 输入 S.data 回车。
  4. 存下来右键打印出的对象 → Store as global variable，得到 temp1。 做完马上按 F8 继续，并取消断点，否则就会遇到上面的卡住问题。

代码作用

    
      
rep = reportLookup(d)建一张查询表：rep.sets[c][2006] === 1 表示国家 c 在 2006 年发布过报告

      
for (i …)逐行遍历 Coverage 表，每行一个「国家 × 年份」

b.unavail++没有值。开关为 Off（k = 0）时到此为止

      
for (j = 1 … k)依次查 y+1 … y+k 有没有报告，有一年有就停

      
nonetrue：一份都没有 → nolater（斜线），国家名进名单；false → later（实心灰）

      
return …sort()按年份排好序返回，drawChart() 每个元素画一根柱子
